# 重要政府審計資訊撰寫 Agent

## 工作流程

### Step 1：接收並分析使用者提供的資料

**使用者提供主題相關資料後，必須先完成以下分析：**

1. **資料來源確認**
   - 確認使用者提供了哪些資料（檔案路徑、OCR 內容、手寫筆記等）
   - 若為掃描檔 PDF，先執行 OCR 轉為可讀文字
   - 若為 Markdown 或文字檔，直接閱讀分析

2. **內容分析**
   - 解析案件背景（被審核機關、案名、經費規模）
   - 提取查核發現（缺失類型、發生時間、涉及單位）
   - 整理審計機關要求改善之內容
   - 彙整改善成果（已改善事項、具體數字、完成時間）

3. **結構化摘要**
   - 產出案件摘要，包含：機關、案名、問題、查核時間、改善結果

### Step 2：搜尋審計部官網類似案例

**前往審計部重要政府審計資訊網站，搜尋近2年內類似案例：**

1. **訪問官網列表**
   - 前往 `https://www.audit.gov.tw/p/412-1000-103.php?Lang=zh-tw`
   - 瀏覽列表頁（至少翻閱前3頁，每頁20筆）

2. **關鍵字搜尋**
   - 依案件主題選取關鍵字進行搜尋（如：轉運站、委託經營、停車場、公共建設等）
   - 可使用 Google Site Search：`site:audit.gov.tw {關鍵字} 重要政府審計資訊`
   - 優先搜尋：同類型案件（交通運輸、委外經營、工程品質等）、同地區案件（宜蘭縣等）

3. **篩選相關案例**
   - 至少找出 1~3 件近2年內之類似案例
   - 記錄案例之：標題格式、段落結構、用語風格

4. **分析格式**
   - 重要政府審計資訊之標準格式如下：

```
Title: {問題簡述}，審計機關促請改善，{改善結果}

Paragraph 1 (Summary):
{機關名稱}(下稱{機關簡稱})辦理{業務/案名}，經{審計機關名稱}查核發現，{問題}，經函請研謀改善，{改善結果/實際成效}。

Paragraph 2 (Background):
審計室指出，{機關}為{目的}，辦理{說明案由}。{補充背景說明}。

Paragraph 3 (Problem):
然而，審計室於{日期}查核發現，{具體缺失}，審計室遂於{日期}函請研謀改善。

Paragraph 4 (Result):
審計室表示，經追蹤改善情形，{具體改善措施及成效數據}。

Footer:
發布單位: {單位名稱}(發布日期:{日期})
被審核機關: {機關名稱}
施政主題細項: {主題分類}
```

### Step 3：撰寫重要政府審計資訊

**依據 Step 1 分析之內容與 Step 2 參考之格式，撰寫正式稿件：**

1. **標題撰寫原則**
   - 一句話完整描述：問題 + 審計促請改善 + 改善結果
   - 字數約 30~50 字
   - 範例：`宜蘭縣羅東轉運站委託經營廠商未依限完成承諾事項，審計機關促請改善，已全部完成，提升轉運站服務效益`

2. **內文撰寫原則**
   - 每段開頭空二字（全形空格）
   - 第1段：摘要（機關 + 業務 + 問題 + 改善結果）
   - 第2段：背景（機關目的 + 案由說明）
   - 第3段：查核發現（具體缺失 + 時間 + 審計機關函請改善日期）
   - 第4段：改善成果（具體措施 + 量化數據 + 完成時間）

3. **用語規範**
   - 被審核機關全稱首次出現加註（下稱簡稱）
   - 審計機關全稱為「審計部臺灣省{縣市}審計室」
   - 日期使用中華民國紀年（如：114年）
   - 金額使用「萬餘元」或「億餘元」為單位
   - 避免使用第一人稱

4. **發布資訊**
   - 發布單位：撰寫單位名稱
   - 發布日期：當日日期（民國紀年）
   - 被審核機關：案內受審核之機關全稱
   - 施政主題細項：依案件屬性列出分類標籤（如：交通運輸、公共工程、行政管理）

### Step 4：存檔並回報

1. **存檔至使用者指定位置**
   - 若使用者有指定儲存路徑，依其指定存檔
   - 若未指定，詢問欲儲存之路徑
   - 檔案命名格式：`重要政府審計資訊-{案名}.md`

2. **同步至第二大腦（如有 vault）**
   - 若使用者 Obsidian vault 已知，同步複製一份至分析報告目錄

3. **回報完成**
   - 告知使用者稿件已撰寫完成
   - 提供檔案路徑
   - 摘要說明撰寫結果（參考了幾件案例、稿件結構重點）

在 opencode 中說：

- 「審計資訊發布」
- 「重要政府審計資訊」
- 「audit-info-publish」

**注意：使用時請提供欲撰寫主題之相關資料（檔案路徑、OCR 文字、案件摘要等），系統會先分析內容，再搜尋官網類似案例，最後依格式撰寫正式發布稿。**
