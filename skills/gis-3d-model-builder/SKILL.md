# GIS 3D Model Builder

## 核心原則

把模型視為 GIS 成果，不是美術場景。所有可定位物件必須有座標、來源、版本、精度或限制說明。政府公開資料是空間與屬性的主要依據；Google Maps用於使用者選點、時相比對與最終視覺校色，不得冒充政府底圖、法定座標來源或可再散布的成果底圖。

嚴格分成兩階段：先完成「GIS 3D基礎模型」，取得使用者明確確認後，才能進入「加值分析／互動功能」。使用者未確認基礎模型前，不得自行加入淹水、水文、防災或其他專題分析。

`3d-builder`、Blender 或 Three.js 僅可協助幾何表現、材質、效能與互動，不得取代 GIS 取資、座標轉換、地理配準、覆蓋率檢查與來源追溯。

## 強制執行順序

以下順序是狀態機，不得因已有範例或先前模型而跳過確認關卡：

1. **Google Maps選點**：在編輯器可控制的瀏覽器開啟Google Maps，請使用者點選／落針要製作模型的位置；讀取並回顯WGS84經緯度、地名與畫面範圍，等待使用者確認。
2. **建立20公里AOI**：以確認點建立半徑20,000公尺範圍，保存WGS84及TWD97 bbox／polygon。20公里作資料盤點與2D背景整合；高細節3D範圍另依建物密度、用途與效能分級，不可假裝所有20公里均已有同等精度。
3. **政府公開資料盤點**：盤點AOI內NLSC正射影像、BUILDX、DTM／DSM、道路、河道／水系、橋梁、公共設施、地籍參考、建管開放資料與實價登錄；逐層記錄可下載、需申請、只能查詢或缺資料。
4. **整合2D基礎圖層**：下載或合法介接可用圖層，統一CRS、裁切AOI、建立圖層開關與`asset-registry.json`，先完成20公里概覽，再建立高細節建模區。
5. **2D空間品管**：核對正射影像、建物框、道路、河道、DTM及既有工程設施；輸出缺漏、錯位、時相差異與涵蓋率。未通過不得建3D。
6. **詢問追加圖說**：主動詢問使用者是否另有建物設計圖、公共工程設計／施工／竣工圖、測量成果或BIM需要納入。等待「無」或檔案提供完成後才繼續。
7. **建立既有3D模型**：以footprint、建管公開資訊、NLSC三維建物屬性、DSM-DTM及可可靠匹配的實價登錄公開欄位建立既有量體；正式樓層與視覺分層分欄。
8. **建立新增／設計工程模型**：以已配準圖說、圖載座標、尺寸、高程及設計狀態建模；與既有時相分層，未完工物件先用白模。
9. **3D空間與屬性品管**：逐棟檢查底圖上有建物但模型缺漏、模型落入河道、footprint偏移、樓層誤綁、工程軸線或高程錯誤；修正後再驗證。
10. **逐物件渲染**：在使用者指定的渲染參考影像上，以每棟footprint／設施範圍內的像素獨立取色；不得用全區單一色盤、鄰棟顏色或未配準截圖。既有物件可參考Google現況影像校色；設計／未完工工程維持白模，除非圖說有正式塗裝規範。
11. **基礎模型驗收**：交付2D圖層、3D建物、工程模型、DTM、點擊資訊、來源表與QA結果，請使用者確認。狀態只有在使用者明確同意後才可設為`BASE_MODEL_USER_APPROVED`。
12. **詢問是否加入分析功能**：基礎模型確認後，提供水文／河川、防災與避難、淹水、坡地／地形、交通可達性、工程進度／維管、土地與建管、其他自訂等選項，也允許選「不加入」。
13. **逐項釐清需求**：對每個已選功能依序詢問分析目的、使用對象、情境／時間尺度、精度、輸入資料、互動方式、輸出格式及決策用途；一次只處理一個功能，並提出資料與方法建議。
14. **分析功能確認**：列出將新增的功能、資料、方法、限制與預期畫面，等待使用者明確確認後才實作。
15. **實作與功能驗證**：在已核准的基礎模型內新增功能，不得改動已通過QA的幾何；驗證計算、互動、匯出、效能及來源追溯。
16. **最終使用者驗收**：展示新增功能及驗證結果，再請使用者確認是否符合需求；未確認前狀態為`FINAL_USER_APPROVAL_PENDING`。

狀態順序：

`LOCATION_CONFIRMED` → `AOI20KM_DEFINED` → `GOV_DATA_INVENTORIED` → `BASE_2D_QA_PASS` → `ADDITIONAL_DRAWINGS_CONFIRMED` → `BASE_3D_QA_PASS` → `MATERIAL_QA_PASS` → `BASE_MODEL_USER_APPROVED` → `ANALYSIS_SKIPPED`或`ANALYSIS_REQUIREMENTS_CONFIRMED` → `ANALYSIS_QA_PASS` → `FINAL_USER_APPROVED`。

## 必要工作流程

依序執行，除非使用者明確縮小範圍。任一空間品管關卡未通過時，不得宣稱模型完成。

### 1. Google Maps選點與專案資料契約

優先在使用者可見的編輯器瀏覽器開啟Google Maps，請使用者點選或落針。由分享網址、座標顯示或使用者確認取得WGS84點位；不可由模糊截圖猜座標。回顯經緯度、TWD97轉換值與地名，取得確認後再建立半徑20公里AOI並記錄：

- 選點WGS84座標、20公里AOI polygon／bbox、高細節3D範圍、主CRS、垂直基準、成果日期。
- 使用者提供的截圖、座標、圖說及分析報告。
- 基礎成果：20公里2D套疊、分級LOD 3D建物、工程構造物、地籍／建管／實價登錄參考、DTM與點擊資訊。
- 加值分析暫列為「未詢問／未確認」，不得在基礎模型階段預設加入。
- 精度目標與用途；查核展示與工程設計不可混為一談。

臺灣工程案若圖說採 TWD97/TM2 121，主運算 CRS 優先設為 `EPSG:3826`；網頁相機或外部服務才轉 WGS84。垂直高程需另列 `TWVD2001`、潮位基準或未知，不可只寫 EPSG。

### 2. 政府資料盤點與可用性分級

先讀 [references/government-data-sources-tw.md](references/government-data-sources-tw.md)。依下列順序搜尋：

1. 原主管機關公開下載、WMTS/WMS/WFS、資料集或正式申請資料。
2. 政府資料開放平臺、TGOS 或主管機關發布的靜態檔。
3. 政府網站公開檢視圖層，僅作參考套疊或人工查詢。
4. 第三方資料只作輔助驗證，不可覆蓋較可靠的政府來源。

20公里AOI至少盤點下列類別，即使最後結果為需申請或無可用資料也要記錄：NLSC PHOTO2／正射影像、BUILDX／三維建物、DTM／DSM、通用電子地圖道路與橋梁、水利署河川／排水／水系、公共設施與工程、地籍參考、中央或地方建管公開資料、內政部實價登錄公開資料。實價登錄只可輔助區位、建物型態、屋齡、樓層或用途核對；不得顯示個人資料，也不得把交易層次直接當成整棟樓層。

每個圖層要在 `asset-registry.json` 或等價 manifest 留下：主管機關、圖層名、原始 URL、擷取日期、資料版本／影像年份、CRS、解析度、授權、涵蓋範圍、取得方式、檔案雜湊、用途、限制與目前狀態。

不要規避登入、API 金鑰、使用條款或服務限制。公開檢視圖層若無合法向量下載，標示為「參考衍生」，不得稱為法定界址或正式建管資料。

### 3. 最新版本與涵蓋範圍檢查

「最新資料集」不等於「研究區影像就是最新年份」。需分別檢查：

- 服務目錄最後更新日。
- 研究區實際圖磚的影像年份或浮水印。
- 是否存在解析度更高但不涵蓋研究區的航測／UAS 資料。
- DTM 版本、實際航測日期、網格大小、垂直基準與 NoData。

若更高解析度資料不涵蓋研究區，保留查詢證據，採用實際有覆蓋且最新的官方圖層；不可將舊影像誤稱為最新。

### 4. 取得與保存官方底圖

優先使用無道路、地名及 POI 標註的官方正射影像。官方浮水印與出處標示不是地圖標籤，必須保留，不得移除、修補或生成式重畫。

網頁底圖至少提供「政府正射影像（衛星圖類）／政府電子地圖／DTM地形設色」等可辨識選項，並明列圖層名稱、年份、服務及授權。大尺寸正射影像不得在尚未完成GPU貼圖時靜默關閉載入狀態；應採4096以下Web版、分塊LOD或瀏覽器按需介接，並提供EMAP／DTM失敗備援與狀態提示。NLSC一般WMTS雖可免API金鑰瀏覽，仍不得大量快取後放到自有伺服器轉供；公開成果優先即時介接，若需再散布整幅衍生影像，應先確認授權。Google圖磚或截圖不得成為可再散布底圖。

WMTS 擷取應限於研究區、合理縮放層級與必要像素，避免大量快取。輸出正射影像、world file 與 metadata；若要離線包裝，先確認服務條款與散布限制。

可執行：

```powershell
python scripts/download_nlsc_ortho.py --extent <xmin> <ymin> <xmax> <ymax> --zoom 19 --size 4096 --output <jpg> --metadata <json>
python scripts/download_nlsc_overlay.py --layer BUILDX --extent <xmin> <ymin> <xmax> <ymax> --zoom 20 --size 4096 --output <png> --metadata <json>
```

### 5. 地理配準工程圖說

先辨識圖說 CRS、比例尺、坐標格網及北向。至少使用 4 個分散控制點，建議 6 至 12 個；另保留不參與求解的檢核點。

配準報告必須列出：

- 控制點像素與目標座標。
- 轉換模型（仿射、投影或薄板樣條）及採用理由。
- 訓練控制點 RMS、獨立檢核點 RMS、最大誤差。
- 掃描、紙張變形與線寬造成的限制。

若誤差高於使用者要求或未設定時高於 5 公尺，標示 `SPATIAL_QA_FAIL`，先修正控制點或轉換模型。不得靠目視拖動工程模型來掩蓋配準失敗。

### 6. 建物、河道、道路與工程構造物建模

先執行「既有空間骨架先行關卡」，順序不得顛倒：

1. 以官方正射影像、正式 footprint／參考建物框及 DTM 建立既有建物、道路、河道與既有設施。
2. 完成建物 coverage census，並抽查正射屋頂、道路轉折、兩岸水涯及既有工程軸線；記錄缺漏、錯置及不同時相。
3. 只有既有空間骨架達到 `SPATIAL_QA_PASS`，才能依已配準圖說或圖載座標建立新建建物／公共工程設施。
4. 若既有骨架未通過，新建模型狀態必須是 `BLOCKED_BY_EXISTING_SPATIAL_QA`，不得渲染成正式位置，也不得先綁定地籍、建管或風險屬性。

Google 地標或截圖上的圖釘只能協助辨識名稱與時相，不能取代既有設施的官方影像數化、竣工座標或新建工程的圖說控制點。既有與新建位置相近時仍須分別保存位置依據及日期，禁止為了視覺好看而共用同一中心、角度或軸線。

建物 footprint 優先使用正式向量；只有公開參考影像時，允許由官方建物框 raster 向量化，但每筆必須標為 `REFERENCE_DERIVED`。高度依序採官方 LOD／建管樓層、實測、DSM-DTM、最後才是視覺估計；估計高度不得當作建管事實。

樓層屬性必須強制分欄：`officialStoreys` 只能來自 NLSC 三維建物 `BUILD_NO`／`NO_SOURCE`、可空間綁定之建照／使照或其他正式紀錄；`modelStoreys` 只控制視覺分層。未取得正式來源時 `officialStoreys = null`，畫面與匯出均顯示「待官方資料核對」，不得把依高度除以3.3、屋頂影像或模型造型推估的層數寫成真實樓層。

建立 coverage census：

- 官方建物框總數。
- 已生成 3D 模型數。
- 遺漏、重複、超出陸域、與河道相交、面積異常數。
- footprint 與正射屋頂的 IoU 或邊界偏差抽查。

河道需區分「影像判釋水涯線」、「河川區域線」及「水利模型計算網格」。影像判釋線可讓視覺水體貼合正射影像，但不能冒充法定河川界。魚塭、陰影與道路不可誤判為河道。

工程構造物要由已配準圖說的軸線、尺寸與高程生成；若圖說與既有影像呈現不同時相，分成「既有」與「設計／施工」圖層，不可硬移到同一位置。

### 7. DTM 與垂直資料

DTM 用於地形骨架與粗尺度集水趨勢。20 公尺 DTM 不足以決定單棟建物門檻、室內地坪、堤頂細部或小尺度淹水深度。這些項目需要測量點、設計高程、較高解析度 DEM/DSM 或現勘資料。

生成 terrain mesh 前檢查：

- 網格涵蓋完整、無錯誤拼接與 NoData 尖峰。
- 單位、垂直基準與情境水位一致。
- 河道與橋梁附近沒有因影像或人工遮罩造成不合理隆起。

### 8. 屬性與點擊資訊

只有通過 footprint／構造物空間品管後，才能綁定地籍、建管、工程與風險屬性。點擊面板至少顯示：

- 物件 ID、類型、名稱或匿名化代碼。
- 坐標、地面高程、模型高度及各欄位來源。
- 地籍參考段、小段、地號或公開查詢連結；明示「僅供參考，不作界址認定」。
- 建管資料的公開欄位、查詢日期與未取得原因；不得呈現所有權人等個資。
- 實價登錄只顯示可合法公開且已可靠空間匹配的非個資欄位、資料期間與匹配信心；交易樓層、總樓層及建物型態需分欄，不得由單筆交易誤推整棟現況。
- 正式樓層、樓層來源與模型分層須分開；模型分層必須附註「僅造型」。
- 工程圖號、構造尺寸、設計狀態及來源頁次。
- 風險情境、計算方式、限制與引用來源。

無資料時顯示「尚未取得／待申請」，不可編造。

### 9. 基礎模型確認後的分析功能

本節只有狀態已達`BASE_MODEL_USER_APPROVED`時才可執行。先詢問是否需要加值分析，並提供可複選清單：

- 水文／河川流量與水位。
- 防災、避難與脆弱度。
- 淹水／暴潮／複合災害。
- 坡地、集水與地形。
- 交通可達性或設施服務範圍。
- 工程進度、施工風險、操作與維護。
- 土地、地籍、建管與都市計畫查詢。
- 其他使用者自訂功能。
- 不加入分析，只保留GIS 3D基礎模型。

對每個已選功能依序詢問：`目的`、`使用者`、`決策問題`、`情境與時間尺度`、`精度／容許誤差`、`可提供資料`、`希望的互動`、`匯出格式`。先根據政府資料可用性與模型限制提出建議，整理成待建功能規格，等使用者明確確認後才實作。不同功能不得一次含混合併詢問。

若選擇淹水或水文，必須依此順序：

必須依此順序：

1. 讀設計計算書、基本設計、分析報告與圖說，建立邊界條件、洪峰、外水位、閘門／抽水站操作、堤頂與施工條件。
2. 尋找主管機關淹水潛勢、河川斷面、雨量、潮位、歷史淹水及官方技術文件。
3. 只有在邊界條件、地形解析度、糙度、計算網格及校核方法具備時，才可稱為 1D/2D 水理模擬。
4. 單一水平水面與 DTM 相減只能稱「水位門檻／靜態淹水概估」，不得稱為動力淹水模擬。
5. 以設計報告既有淹水圖、面積、深度或歷史事件校核；列出誤差與無法驗證部分。

洪峰情境必須採「評估年份 → 重現期 → 流量口徑」三層結構。每個情境至少保存 `analysisYear`、`returnPeriod`、`peakFlow`、`flowDefinition`（天然／現況／計畫／高地／目標年）、`waterLevel`、`section`、`levelQuality` 與來源頁表。不得把相同數值在不同年份或不同口徑下視為同一水文事實。設計報告未提供某年份 Q50／Q100 時，應停用並顯示未計算；如為風險篩檢而插值或外推，必須標為 `SCREENING_ESTIMATE`，且不得冒充正式水理成果。

風險分級、暴露建物與水深表均保留公式、資料版本及不確定性。若建物地坪只是 20 公尺 DTM 取樣，點擊資訊與 CSV 必須明示。

網站至少提供兩種匯出：一是目前年份／重現期／微調水位下，經連通判定之全部風險建物 CSV；二是全部建物×全部可用正式／篩檢情境之 JSON/CSV 風險矩陣。欄名一律使用正體中文，且須盡量完整帶出已知建物資料：識別碼、名稱、LOD、幾何品質、TWD97座標、面積與尺寸、地面高程及依據、模型高度、正式樓層及匹配狀態、模型造型樓層、現況色、材質／足跡來源、建管／實價／地籍匹配狀態、距分析源點、洪峰、水位品質、水深、風險級別、連通狀態、方法與限制。`開始風險條件`不可只寫「Q10」等模糊字樣，應明列在目前基本設計的哪個評估年份、重現期、洪峰流量、斷面水位及資料品質下開始具風險；若只在手動水位偏移下發生，須明示該偏移為敏感度試算而非報告列值。所有CSV匯出的最後兩欄固定為 `資料來源`、`出處`；前者列資料集／文件名稱，後者列URL、專案檔案、報告頁表或圖號。JSON需提供等價的逐筆欄位及頂層 `sourceCatalog`。

選擇特定年份及洪峰情境時，若專案用途包含決策支援，顯示兩組可追溯建議：審計觀點聚焦核定口徑、契約義務、預算期程、操作紀錄及風險治理；水利工程觀點聚焦水理重算、斷面與高程補測、閘門／抽水站操作、複合事件及不確定性。兩者不得混成無來源的一般性結論，亦不得取代主管機關核定或技師簽證。

若使用網格作風險溝通，網格必須從河道／外水邊界種子依連通關係向外擴散，不得把與河道不連通的低窪格直接畫成同一洪水。河道種子不可只畫一條任意中心線：應優先取得政府公開河川面／水系；若免申請條件下只能取得NLSC臺灣通用電子地圖開放版等raster，須先把圖面水域分類，再與經正射影像核對的河道中心線走廊及分析源點連通元件取交集，明確排除海域、魚塭及不相連水體。WFS若標示須申請，不得把未取得向量寫成已介接，可改用免金鑰開放WMTS作圖面參考並保留限制。陸域外溢應至少以DTM最低鞍部／priority-flood或等價方法控制，不得只按距離畫同心擴散。

水位控制的最低值應能呈現明確「無外溢網格、無風險紅棟」基準；動畫播放不得沿用目前水位直接開始，應先回到最低值並保留可辨識的乾燥起始幀，再依水位、最低鞍部及河道抵達距離向外推進。只有建物實際footprint／量體投影與當前連通淹水格相交，且情境水位高於粗估地面高程，才可判為受影響，不得只以建物中心點或固定鄰格判定。所有受影響建物必須同步顯示為可辨識的紅色系，低／中／高／極高以不同紅色深淺保留差異；深色底圖或場景光照下應增加不受光照影響的紅色覆層，並以機器QA確認`redRenderedCount == riskBuildingCount`。不得只驗證內部材質或實例色計數，還須在固定鏡位關閉其他紅色線層後讀取WebGL畫面或截圖，確認乾燥幀紅色像素為0、推進及最高水位紅色像素顯著增加。Three.js舊版若同時使用`InstancedMesh.setColorAt()`與`vertexColors:true`，必須確認geometry有全白`color` attribute，避免實例色被缺省黑色相乘。離開風險後恢復原材質。此方法仍只能稱為連通式靜態水位／最低鞍部外溢概估，不能稱為 2D 動力水理模擬。

場景方向資訊應另建可開關的建物、道路、河川、工程／橋梁／公共設施、景點／地標等分類標籤；總開關與各分類開關應分開，名稱與位置優先取政府公開電子地圖、道路／河川／地標資料，記錄圖層、擷取日、位置誤差與是否為圖面數化。標籤不得直接燒錄在無文字正射底圖上，且應依縮放距離、優先級與畫面碰撞自動隱藏，避免遮蔽模型。

互動視角至少同時提供固定快速視角及「自由瀏覽」模式。自由瀏覽啟用後，使用者點模型任一位置即可重設旋轉中心，並可旋轉、縮放；按滑鼠右鍵應在OrbitControls執行平移前直接退出自由瀏覽，退出後立即恢復物件點擊資訊。右鍵退出宜在canvas的capture-phase `pointerdown`攔截並阻止同一事件繼續傳給控制器，另抑制瀏覽器context menu。不得以鎖死視角冒充自由瀏覽，也不得讓自由瀏覽點擊同時誤開物件彈窗。大量建物若採`InstancedMesh`，每個instance都必須以合法`instanceId`解析至唯一建物ID；需驗證資料筆數、唯一ID數、instanceColor數及可點擊筆數一致，並至少實點分散樣本開啟正確資訊，不得只驗證整批mesh可被raycaster命中。

### 9A. 模型優先的桌機／手機 UI 硬性規則

互動網頁必須把桌機、直立手機及橫向手機視為不同驗收狀態，不能只等比例縮小桌面介面。UI 配置以「優先保留完整模型畫面」為最高原則，並遵守下列規則：

1. 3D canvas 必須是預設畫面的主體；圖層、物件資訊、分析、查核或證據面板預設收合或隱藏，不得在首次載入時遮住模型主要構造物。
2. 同一時間原則上只展開一個主要面板。開啟新面板時應自動收合其他面板；離開功能或按關閉後，立即把視野還給模型。
3. 固定視角與模式快捷列採緊湊邊緣排列，使用「全景、頂視、斜視、近看、無人機」等可直接理解的短名稱，完整說明放在 `title`、提示文字或次層資訊；不得讓快捷列橫跨並遮蔽模型中央。
4. 主按鈕名稱必須描述使用者可得到的結果或要執行的動作，例如「查看預擬查核意見」、「檢查主張」、「下載證據」。`AUD-01`、資料表名或英文字代碼只能作為次要識別，不可單獨作為主要操作名稱。
5. 桌機版展開的邊緣面板建議寬度不超過 260px；若內容較多，採抽屜或對話框並預設關閉。工具列及狀態列應避開工程主體，不因固定定位大幅縮減可視模型面積。
6. 直立手機不得固定套用永久底部面板，也不得把桌機工具列全部鋪滿螢幕。預設只顯示緊湊的邊緣按鈕；使用者主動展開時才顯示可捲動面板，並保留清楚的關閉方式。
7. 觸控命中區至少 44×44px，但視覺外觀可藉由留白、透明命中區與圖示維持緊湊。頁面必須支援 `100dvh`、`viewport-fit=cover`、上下安全區，且不得水平溢出。
8. 模式專用控制只在模式啟用時顯示。操作方式以使用者指定為準；例如網頁版已指定方向鍵控制時，不得另加大型螢幕搖桿。若手機需要不同輸入方式，須先取得使用者確認。
9. 依空間近接自動出現的提示卡應小型、可讀且不阻擋前進方向，離開觸發範圍後自動關閉。涉及查核疑義時須標明「預擬／待查證」或「已證實」，不得把 C／D 級判讀或缺資料狀態呈現為已證實缺失。
10. 至少以桌機 1440×900、直立手機 390×844 及橫向手機 844×390 進行視覺與操作 QA：檢查預設可視模型面積、主體遮蔽、面板互斥開關、按鈕命名、觸控尺寸、內容捲動、文件水平溢出及模式控制顯示時機。驗收紀錄須列出各尺寸的失敗項與修正結果。

上述規則取代「手機一律使用底部面板／底部快捷列」的固定版型要求；實際位置應依模型主體與操作情境決定，但預設必須收合、緊湊且不遮景。

若需製作水利專家問卷，目的應限定為協助審計人員強化對機關之查核意見，原則上濃縮為6至8個核心問題。每題均要求專業判斷與理由、機關具體改善措施、可驗收量化目標／期限、應補調證據及可直接納入查核意見之文字；題後附明確報告頁表、圖說、政府資料集或技術文件出處，避免全面性學術審查或大量重複題目。

分析源點（例如閘門、抽水站、決口或工程基地）與網站資料邊界間必須保留可說明的水理緩衝距離。若使用者要求以該點為模型中心，應把**資料範圍的幾何中心**設為該點，而不只是調整相機目標；完成後須以 CRS 座標計算中心差並驗證。範圍大小應由集水區、排水分區、報告淹水包絡、上下游及側向邊界共同判定，不得只為畫面美觀採任意方框。矩形若含海域、山地或集水區外土地，必須明示其面積不能與淹水面積或集水區面積直接比較。

DTM 無資料區必須建立有效資料遮罩。外海缺少浴深時，不得把顯示用 EL 0 或其他填充值當成陸域低地參與淹水格網、受影響建物計數或統計；海岸、暴潮、越波及海陸交換另須具備浴深與正式邊界條件。若為網站效能將政府 DTM 抽樣成較粗分析格網，清冊、畫面與匯出資料必須同時保留「來源解析度」與「分析／顯示解析度」。

設計報告中的集水區、低地或淹水邊界若僅能由 PDF 圖面目視數化，應降低座標有效位數、記錄來源圖號／頁次與概估誤差，並在圖層名稱明列「圖面概化／非原始模式向量」。概化線可作可隱藏的查核參考，但不得量測面積、作法定認定或替代 SOBEK、HEC-RAS、SEC-HY21 等原始網格／向量成果。

### 10. 代表區、基礎模型驗收與批次擴建

先完成包含道路、河道、建物及至少一項工程構造物的代表區。讀 [references/qa-gates.md](references/qa-gates.md) 執行俯視、斜視、點擊與資料追溯檢查。

狀態依序為：

`SOURCE_ACQUIRED` → `GEOREFERENCED` → `SPATIAL_QA_PASS` → `ATTRIBUTE_QA_PASS` → `USER_APPROVED`。

有重大錯位或美術品質不足時設為 `REJECTED_ART_QUALITY` 或 `SPATIAL_QA_FAIL`，保留失敗理由並從正式成果排除。只有代表區經使用者核准，才批次擴建高細節3D範圍。完成全部基礎2D／3D、材質、點擊資訊與來源QA後，必須另行請使用者確認整體基礎模型；只有明確同意才設為`BASE_MODEL_USER_APPROVED`並詢問加值分析，不能把代表區核准直接當成分析功能授權。

### 11. 驗證後材質渲染

只有 footprint、工程線位、coverage census 與點擊屬性均通過品管後，才執行最終材質渲染：

1. 先明確指定「渲染參考影像」。每棟建物屋頂與每項工程設施都只能由自身已配準footprint／範圍內像素獨立取樣；保存影像來源、時相、取樣像素數、統計方法及色碼。不得套用全區平均色、鄰棟色或未配準影像的同座標像素。
2. 正射影像看不到的立面色只能標為衍生色或現勘資料；不得宣稱為實際立面顏色。
3. 完成幾何QA後，在Google Maps進行最終現況色彩核對。若使用者確認Google影像為渲染參考，依每棟footprint／既有設施範圍計算中位色碼，但只保存衍生色碼、取樣統計與來源，不得把Google像素做成可散布紋理或成果底圖。若使用者指定「依目前底圖顏色」，則必須改由畫面實際顯示的已配準底圖逐物件取色，不能仍取另一張Google截圖。單一錨點配準只能標為`VISUAL_REFERENCE_SINGLE_ANCHOR_REGISTRATION`，不得移動GIS幾何。
4. 嚴格區分時相：既有建物／既有設施可採現況色彩；新建、設計或尚未完工工程預設固定白模 `WHITE_MODEL`，除非設計圖已有明確塗裝規範且使用者要求套用。不得把現況衛星色彩誤套至未來工程。
5. 網頁提供「現況色彩＋新建白模」與「全區白模空間檢核」渲染模式；淹水危及時依水深分級覆色，離開風險狀態後恢復目前渲染模式。
6. 完成俯視、45度斜視與近景比對，確認材質沒有掩蓋錯位、缺棟或錯誤時相；輸出 `material_palette.json`、材質來源表與QA截圖。
